## Primary Questions

1. Is every production prediction generated by the same canonical prediction engine path?
   - Production surfaces consume persisted Current Era `prediction_history` rows through Current Board or Performance. Multiple legacy/preview engines exist, but production actionability is scoped by `is_current`, active epoch, production eligibility, and product gates.

2. Do product surfaces consume the same canonical prediction universe?
   - Homepage, Dashboard Today, Current Board, Most Likely, Best Value, Betting Workbench, and Game Intelligence are Current Board-derived for current betting evidence. Performance uses `performance-scope-v2` over `prediction_history`, which is an expected scope difference.

3. Where does every current MLB market price come from?
   - `sports_odds_snapshots` when a safe, matching row exists; otherwise stored `prediction_history.odds` may be used for source-side evidence. Displayed complement outcomes do not currently receive a complement-side price rebind.

4. Why can provider calls write snapshots while predictions still show Odds N/A?
   - Current Board binds latest odds only for the stored prediction side and exact line. If the product displays the binary complement as the higher-probability canonical outcome, `canonicalPrice` becomes `NO_OPPOSITE_PRICE`.

5. Is the latest provider-backed market row selected correctly?
   - For source-side identity matches, yes: `latestSafeOdds` filters by event, market alias, normalized selection, exact line, and freshness/safety, then sorts by selected freshness timestamp. For complement display, no second lookup is attempted.

6. Is source/provider timestamp persisted correctly?
   - Repository evidence shows `canonical-acquisition.service.ts` writes `provider_timestamp` and metadata provider timestamp. Production evidence exposes source timestamp separately from capture timestamp.

7. Are market identity keys aligned?
   - Mostly aligned for source side. Known gap: complement-derived display side is not rebound to opposite odds identity.

8. Are predictions generated before canonical odds exist and never refreshed/rebound?
   - Current Board requires non-null `prediction_history.odds`, so no truly odds-less prediction enters Current Board. However, later market refresh rebinding is source-side only, not complement-side.

9. Does market refresh update only odds snapshots or canonical prediction/current-board evidence?
   - Provider refresh writes `sports_odds_snapshots`; Current Board reads through to bind safe latest odds. It does not mutate prediction rows during read-through.

10. Are any surfaces reading stale/legacy paths?
   - Legacy/preview paths exist but were not proven to feed actionability. Probability Picks and historical/replay surfaces are informational/diagnostic and separated.

11. Does completed event flow through result, settlement, learning, performance?
   - Current evidence shows settlement/performance pipelines are present and reporting Current Era state. No silent-pending defect was proven in this audit.

12. Are there duplicate/orphaned pipelines?
   - Yes, there are many legacy/preview/shadow engines. They should remain classified and fenced; no production actionability dependency was proven except Current Board/Performance lineage.

## Findings

### HIGH: Complement Price Rebinding Gap

Evidence:

- `current-board.service.ts` stores source-side prediction and price.
- `canonicalOutcome` may flip to the higher-probability binary complement.
- `attachCanonicalOutcomeContracts` sets complement-derived `canonicalPrice` to `NO_OPPOSITE_PRICE`.
- Production examples:
  - `ARI +1.5 Run Line` displayed `Odds N/A`, while source `LAD -1.5` had `+111`.
  - `ARI Moneyline` displayed `Odds N/A`, while source `LAD` had `-199`.

Severity: HIGH.

Safety: not CRITICAL because those rows were blocked by stale Product Freshness SLA and recommendation gates.

Recommended repair: implement a bounded complement-side price lookup in Current Board using exact event, market, opposite normalized selection, exact inverted line for spreads, and same sportsbook/consensus scope. Do not synthesize prices.

### MEDIUM: Dual Freshness Labels Can Confuse Users

Evidence:

- Current Board display freshness can use snapshot capture/ingestion time.
- Product Freshness SLA uses provider market timestamp and blocks actionability.
- Production evidence had capture time around `2026-08-08T20:37Z` but source market timestamp `2026-08-08T16:37Z`.

Severity: MEDIUM.

Recommended repair: label display recency as `Snapshot captured` and actionability recency as `Market evidence age`.

### MEDIUM: Protected Audit Endpoints Require Auth

Evidence:

- `/api/operations/planner-trace` returned 401.
- `/api/operations/e2e-integrity` returned 401.

Severity: MEDIUM for unauthenticated audit completeness only; no runtime defect proven.

Recommended repair: none unless a read-only signed audit path is desired.

### LOW: Legacy/Preview Engine Surface Area Remains Large

Evidence:

- Multiple preview, historical, sport-specific, and diagnostic engines exist.
- Production actionability was not proven to depend on them.

Severity: LOW if fenced; HIGH if a production surface begins consuming them without explicit scope.

Recommended repair: continue classification and documentation, no deletion without proof.
