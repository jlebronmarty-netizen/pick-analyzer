# Pick 2 Data Foundation V1

Status: `PICK_2_RESET_04_DATA_FOUNDATION_CERTIFIED`

Pick 2 keeps stable canonical sports identity in the existing shared tables and adds a separate Pick 2 era for raw MLB data, leakage-safe features, model registry, frozen sports predictions, result evaluation and market-value analysis.

## Domains

- Canonical sports data: reuse `sports_teams`, `sport_players`, `sport_events`, `game_results`, `sport_game_stats`, `sport_player_stats`, `sport_lineups`, `sport_injuries` and `sports_odds_snapshots`.
- Raw MLB data: `pick2_raw_mlb_statcast_pitches` stores future Statcast pitch rows by deterministic pitch identity. RESET-04 imports zero rows.
- Derived features: daily feature tables and `pick2_feature_snapshots` store as-of feature inputs with source windows and sample sizes.
- Models: `pick2_model_registry`, `pick2_model_versions`, `pick2_model_feature_sets`, `pick2_model_training_runs` and `pick2_model_validation_runs` isolate champion/challenger lifecycle. Current champion remains `NONE`.
- Sports predictions: `pick2_game_predictions` stores pure sports model output without requiring sportsbook odds.
- Result evaluation: `pick2_prediction_results` stores bounded evaluator output against canonical `game_results`.
- Market value: `pick2_market_value_evaluations` links a sports prediction to `sports_odds_snapshots` only after the pure probability exists.
- Legacy archive: existing `prediction_history`, Official Pick rows, shadow rows, research ledgers and legacy performance data remain `LEGACY_PRE_PICK_2`.

## Identity

Statcast pitch identity is initially `game_pk + at_bat_number + pitch_number`, with a deterministic text `id` generated by the future importer. Replays must be `REUSE_NO_OP`. A conflicting payload digest for the same identity must be blocked or quarantined by the importer.

Feature identities include sport, feature domain, subject, optional event, feature date, as-of date and feature version. Prediction identities include sport, event, model version, target, prediction timestamp class and frozen input digest.

## Leakage Safety

Feature rows require `as_of_date <= feature_date`; importers and builders must enforce stricter timestamp checks when source timestamps are available. Future feature builders must not use post-start or postgame information for pregame predictions.

## Security

New Pick 2 tables are RLS-enabled. Service role owns writes. Authenticated users receive read access only to model/prediction/result/value/data-health tables that are suitable for product reads. Raw and feature-building tables remain service-role only.

## Migration Policy

RESET-04 prepares `supabase/migrations/202608270002_pick2_data_foundation_v1.sql` but does not apply it to production. Production application requires a separate explicit migration-apply authorization.

## Integration Contracts

Data Health will read import-through dates, mapping percentage, feature build dates, odds freshness, model readiness and prediction readiness from Pick 2 health/status data.

Performance will query only `PICK_2_ERA_V1` predictions and evaluations. Legacy rows are excluded from Pick 2 metrics.

Model Lab will query champion/challenger state and validation metrics from Pick 2 model tables. It must show no champion until explicit promotion.

Today will compose canonical slate, latest Pick 2 pure sports predictions and optional market-value evaluations. If no Pick 2 prediction exists, it must show `NO PREDICTION` and must not fall back to legacy `prediction_history`.
